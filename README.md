# Финансовый дневник — Vercel + Supabase

Это Next.js-приложение под одного пользователя.  
Данные хранятся в Supabase PostgreSQL. Доступ закрыт через Supabase Auth и RLS.

## Что внутри

- `app/login` — обычный вход по email и паролю.
- `app/app` — сам финансовый дневник.
- `supabase/schema.sql` — таблицы и RLS-политики.
- `components/FinanceApp.tsx` — основная логика: операции, регулярные платежи, регулярные доходы, чеклист, прогноз, импорт.

## 1. Supabase

1. Создай проект Supabase.
2. Открой SQL Editor.
3. Открой файл `supabase/schema.sql`.
4. Замени строку:

```sql
'REPLACE_WITH_YOUR_EMAIL@example.com'
```

на свой email.

5. Выполни SQL целиком.

## 2. Auth

В Supabase включи Email Auth с паролем.

Для режима только под себя:
- создай пользователя вручную: Supabase → Authentication → Users → Add user;
- укажи свой email и пароль;
- email должен совпадать с `ALLOWED_EMAIL` в Vercel и с email в `app_config` из SQL;
- публичную регистрацию можно отключить.

RLS не даст чужому аккаунту читать или менять твои таблицы, потому что политики проверяют `auth.uid()` и email из `app_config`.

## 3. Локальный запуск

```bash
npm install
cp .env.example .env.local
npm run dev
```

Заполни `.env.local` (`ALLOWED_EMAIL` не имеет префикса `NEXT_PUBLIC_`, чтобы не светить email в браузерном JS):

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
ALLOWED_EMAIL=your@email.com
```

## 4. Деплой на Vercel

1. Загрузи проект в GitHub.
2. Импортируй репозиторий в Vercel.
3. В Vercel Project Settings → Environment Variables добавь:

```env
NEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_ANON_KEY
ALLOWED_EMAIL
```


4. Deploy.

## 5. Вход на сайт

Основной вход выполняется по email и паролю. Маршрут `/auth/callback` оставлен только для безопасного завершения возможных Supabase Auth-потоков и принимает переходы исключительно внутри сайта.

После деплоя открой:

```txt
https://YOUR-VERCEL-DOMAIN.vercel.app/login
```

Введи email и пароль пользователя, которого создала в Supabase Auth.

## 6. Импорт из старого HTML

В приложении:
- открой настройки;
- вкладка `Импорт`;
- загрузи JSON-экспорт старого дневника.

Импорт заменяет текущие данные в базе. Перед импортом сделай экспорт текущей базы.

## Важная логика

- Регулярные доходы не попадают в чеклист, но попадают в прогноз.
- Все активные регулярные платежи, включая кредиты, рассрочки и квартиру, попадают в чеклист.
- Регулярные платежи по умолчанию отображаются с установленной галочкой.
- Снятая вручную галочка сохраняется как исключение только для конкретного платежа и месяца.
- Ручные операции без галочки не считаются.
- Ручные операции с галочкой считаются фактом и группируются по статье.
- У обычных доходов и расходов есть срок действия `С` / `До`; пустое поле означает отсутствие ограничения.
- У кредита нет отдельного поля `До`: оставшийся срок рассчитывается как `Всего месяцев − Оплачено месяцев`, начиная с указанного месяца `С`.


## 7. Вкладка переезда

Добавлена отдельная вкладка `Переезд / мультивалюта`.

Она хранит сценарный план в таблице:

```sql
public.relocation_plans
```

Если ты уже выполняла старый `schema.sql`, отдельно выполни:

```txt
supabase/migration_add_relocation_planner.sql
```

Что умеет вкладка:

- доходы и расходы из разных стран;
- KZT и EUR в одном плане;
- ручной курс EUR → KZT;
- стартовый остаток KZT из дневника и дополнительный резерв в EUR;
- ежемесячные, квартальные, годовые и разовые строки;
- период действия каждой строки;
- Германия gross → примерное netto;
- накопительный остаток по месяцам;
- разбивка Казахстан / Германия.

Калькулятор перенесён не как встроенный Google Sheet, а как нормальная часть сайта с сохранением в Supabase.

## Раздельные периоды дневника и прогноза

Перед публикацией этой версии выполните в Supabase SQL Editor файл:

`supabase/migration_split_diary_forecast_periods.sql`

Он добавляет независимые поля начала просмотра дневника операций и календарного прогноза. Существующее значение `calc_start_month` автоматически переносится в оба поля, поэтому текущие данные не теряются.
