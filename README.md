# Финансовый дневник: Казахстан и Германия

Личное приложение на Next.js, Vercel и Supabase. В верхней шапке два основных раздела:

- **Казахстан** — дневник операций и календарный прогноз;
- **Германия** — расходы по месяцам, общий прогноз Казахстана и Германии и дополнительные сценарные статьи.

## Основная логика

### Казахстан

- Дневник и календарный прогноз имеют независимые начальные периоды.
- Регулярные платежи из настроек отображаются в дневнике как актуальные виртуальные строки, без создания копий в `operations`.
- Платёж включён по умолчанию. Снятая галочка сохраняется как исключение только для выбранного месяца.
- Старые материализованные копии регулярных платежей автоматически удаляются при загрузке; снятые галочки предварительно переносятся в исключения.
- Регулярные доходы участвуют в расчёте прогноза, но не создают лишние строки в чек-листе дневника.
- Выполненные ручные операции группируются по статьям. Группа не разрывается между страницами.
- Доходы, расходы, остаток месяца и накопительный итог визуально разделены.

### Германия

- Параметры сценария, сводка, расчёт немецкого netto и сценарные статьи скрыты под отдельными кнопками.
- Регулярные расходы Германии редактируются в `Настройки → Германия`.
- В основном экране Германии расходы показаны по выбранному месяцу с отдельными галочками. Снятие галочки создаёт исключение только для этой статьи и этого месяца.
- Доходы и разовые расходы хранятся в сценарных статьях.
- Общие статьи доходов и расходов берутся из настроек Казахстана. Переименование или удаление статьи синхронизируется с планом Германии.
- Календарный прогноз содержит весь горизонт планирования. В видимой области помещается примерно 15 месяцев, остальные доступны горизонтальной прокруткой.
- Статьи доходов и расходов раскрываются независимо кнопками `+ / −`.
- Казахстанские доходы и расходы включаются в общий расчёт отдельными суммарными строками, без двойного учёта.

## Настройки

Разделы бокового меню:

1. Параметры
2. Платежи
3. Кредиты
4. Доходы
5. Германия
6. Статьи
7. Импорт

Таблицы настроек используют встроенные сортировку и фильтры. Изменения сохраняются автоматически через последовательные очереди запросов, чтобы старый ответ не перезаписывал более новое значение.

Кредиты не используют поле окончания. Период рассчитывается по месяцу начала, общему количеству месяцев и уже оплаченным месяцам.

## Резервная копия

Экспорт включает:

- параметры;
- статьи;
- операции;
- регулярные платежи и доходы;
- месячные исключения;
- состояния свёрнутых групп;
- полный план Германии.

Импорт заменяет текущие данные. Перед импортом приложение завершает активные сохранения Германии и останавливает отложенные записи, чтобы старое состояние не перезаписало импортированный план.

> Импорт выполняется несколькими запросами из браузера, а не одной серверной транзакцией. Перед импортом рекомендуется скачать резервную копию.

## Установка

```bash
npm install
npm run build
npm run start
```

Необходимые переменные окружения приведены в `.env.example`:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
ALLOWED_EMAIL=your@email.com
```

Для новой базы выполните `supabase/schema.sql` целиком.

Для существующей базы, созданной старой версией, при необходимости выполните:

- `supabase/migration_split_diary_forecast_periods.sql`;
- `supabase/migration_add_relocation_planner.sql`.

Настройка пользователя и пароля описана в `LOGIN_PASSWORD_SETUP.md`.

## Проверка проекта

```bash
npm run typecheck
npm run build
```
